Together, the 40 slices built the first working core of Reform. Glossary

These are the words used on this page, explained in plain words.

Slice
One small step of work. A slice is planned, then it is built, then it is reviewed twice. A feature slice has its tests written first, before it is built.
Feature
A kind of slice. A feature slice adds new behavior. New behavior means the language can do something it could not do before.
Future
The other kind of slice. A future slice changes how the program is written, with no new behavior. It makes the next slice easier to build.
Tidy
A small clean-up inside a slice. It changes how the program is written, not what it does.
Merged
A slice is merged when its work is finished and joins the main copy.
Landed
A slice has landed when its work is saved and its change request is open, waiting to join the main copy. It has not joined yet.
Commit
The act of saving a program. A merge commit is a different thing: the saved record of a slice joining the main copy.
Merge commit
The saved record of a slice joining the main copy.
Reload
Switching a running program to a new version without stopping it.
Main copy
The shared copy of the program that all the work builds on. A merged slice joins this copy.
Check
One test of the program. A check passes or fails. A health check is different: it is the review that runs after a slice is done.
Health check
The review that runs after a slice is done. It asks whether the code is still easy to change. A second reader reads the program the way the next builder would, and tries three small trial changes to see how hard the next change is. If the open work did not grow, the review passes. If it grew, the next slice must tidy up first. Slice 5 and slice 40 have no health check of their own.
Futures ledger
The record of work still to do, kept after each health check.
Ledger item
One thing still to do, from the futures ledger. Open items are the ones no slice has finished yet.
Debt
Work that is still to do. The Debt section lists each item, with what would finish it.
File
One named piece of the program's writing. The program is written in files. A change to 1 file is a small change.
PR
The short name for the change request that adds a slice's work to the main copy.
Turn
One round of planning. Each turn picks the next slice.
Planner
The role that picks the next slice. The planner reads how the work is going and picks the next small step.
Test author
The writer who writes the tests for a slice, before the slice is built.
Builder
The role that builds a slice. The builder writes the code only, and never touches a test file.
Coordinator
The role that runs the work. It takes each finished slice and joins it to the main copy.
Kernel
One copy of Reform running on one machine.
Caller
A program that asks Reform for work.
Queued call
A call that waits for its turn to run. It runs on the version it had when it was queued.
Server
One side of a call between two machines: the side that answers. A server runs the part the call asks for.
Client
The other side of a call between two machines: the side that asks. A client sends the call and waits for the answer.
Peer
Another copy of Reform on another machine. A peer sends calls and answers.
Store
Where Reform keeps saved programs.
Checkpoint
A saved copy of a whole program version, kept so the program can go back to it. A checkpoint can grow too big, so its size has a limit.
Part
One named piece of a program. Each part promises what it takes in and what it gives back.
Arrow
The promised input and output of one part of a program. An arrow says what a part takes in and what it gives back.
Entry
One part of a program, written down when the program is saved. An entry names the part, what it takes in, what it gives back, and which machine it runs on.
Module
One named group of parts in a program. A module lists the other programs it uses and the parts it shares.
Effects slot
The place in an entry that lists the effects a program uses. An effect is a change a program makes while it runs.
Ready-made operations
Operations that come with Reform, ready to use. They need no definition in the program.
Design
The written plan for Reform, as opposed to the built program.
In flight
A slice is in flight while it is still going. It is not done yet.
Second reader
A reader who reads the plan, the tests, or the finished work after it is written, to catch problems.
Loop 1
The first round of review for a slice. The tests are written first, then a first review and a second review check them, before the slice is built.
Loop 2
The second round of review for a slice. The slice is built first, then a first review and a second review check the finished work, before it is saved.
First review
The first of two readings of the tests, or of the finished work. One second reader reads them and either passes them or sends them back to be fixed.
Second review
The second of two readings, after the first review passes. Another second reader reads them again and either passes them or sends them back to be fixed. A plan has no first review. The planner writes the plan, and a second reader reads it next. That reading is the plan's second review.
Fuel
The work one run of the program is allowed to do. Each run is given a set amount of fuel. A program that never finishes stops when its fuel runs out.
Budget
The amount of fuel one run gets. One budget covers the whole call, even when the call runs on two machines.
Depth
How deep one call can nest inside another call. Each run is given a depth budget. A call that nests deeper than the budget stops.
Rounds
One round is one trip of a call between two machines and back. The rounds in a call are counted once, in one place.
Stack
The space a running program uses to remember calls inside calls. When calls nest too deep, the space runs out.
Thread
One line of work running inside the program.
Gate
The check that runs when work is saved. It refuses to save work that breaks a rule.
Checker
The part of Reform that checks each part's promise before it runs.
Probe
One small check the builder runs by hand, outside the regular checks, to prove one fact about the program.
Root id
The name a saved program gets. It is made from what the program means, not how it is written.
Pin
A marker on a version that says a run is using it, so the version cannot be dropped while the run goes on.
Repair pass
The check that re-judges a whole saved version against its own rules. A version that passes it carries a repair stamp.
Kind
The kind of work a log row records. It says what the row is: the tests written first, a first or second review, a slice built, saved, or joined, a plan picked, a health check, or work on the tracker itself.
Dashboard
This page. It shows the log of the work as it goes.
Tracker
Another name for this page. It tracks the work on Reform, slice by slice, so a reader can follow it.
